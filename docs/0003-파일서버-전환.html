3. 바뀐 구조

3.1 파일 위치·주소

  • 영상·썸네일·채널 프로필 이미지는 모두 file_server(https://sme0582.duckdns.org, 앱 이름 y2b)에 비공개로 있다. y2b 서버 디스크(wwwroot/video, var/y2b_upload, var/y2b_hidden)는 더 쓰지 않는다 (빈 var 폴더 두 개는 지움).
  • DB(yt_video.file_path·thumbnail, yt_channel.avatar, yt_upload.path)에는 토큰 없는 경로만: y2b/yyyy/mm/dd/{유닉스초}.{랜덤12}.{mp4|jpg|png|webp}
  • 응답할 때 Y.ok() → sign_media() 가 MEDIA_KEYS (file_path, thumbnail, avatar, channel_avatar, author_avatar)와 hls_path 를 보기 주소로 바꾼다. 유효 SIGN_HOURS = 6 (정시 내림, 남은 5~6시간). 새 응답 칸에 파일 경로를 넣으면 MEDIA_KEYS 에 추가해야 한다.
  • 볼 권한은 예전처럼 각 API 가 어떤 행을 내보내느냐로 정한다(public_where, can_watch). 서명은 DB 에서 읽은 y2b/ 경로만 한다.

3.2 영상 업로드 흐름

브라우저 → y2b   POST upload/start  {filename, size}
                 로그인·.mp4·max_mb·열린 업로드 3개 확인 → yt_upload 행(token, path)
                 ← {token, url, path, size, chunk:10MB, t(업로드 토큰, 6시간)}
브라우저 → file_server  POST {url}?path=&size=&offset=&t=   본문=조각 바이트 (10MB 씩, 앞에서부터)
                 200 {received, done}  /  409 {detail:{received}} → 그 위치부터  /  403 → upload/renew 한 번
브라우저 → y2b   POST upload/finish {token, title, description, visibility, duration, thumbnail(파일)}
                 행 삭제에 성공한 요청 하나만 진행(동시 finish 방지)
                 → tmp 앞 12바이트를 서명 GET(Range) 으로 읽어 'ftyp' 확인 (아니면 파일 삭제, not_mp4)
                 → commit [path] (tmp → data). 실패하면 행을 되살려 다시 finish 가능
                 → 썸네일은 서버 간 data_upload → yt_video 저장
실패·그만둠  → POST upload/cancel {token}  행 + file_server tmp/.part 삭제
  • 올리다 만 파일은 file_server 가 24시간 뒤 tmp 정리. 하루 지난 yt_upload 행은 다음 upload/start 때 지운다.
  • MP4 검사가 예전엔 첫 조각에서, 이제는 finish 에서 한다 (file_server 는 내용을 보지 않는다).

5. 설계(0004 §13)와 다르게 한 점

  • 썸네일은 브라우저 → file_server 가 아니라 y2b 서버가 받아 서버 간 업로드. 2MB 이하라 단순하고, 서버에서 이미지 바이트를 검사할 수 있다.
  • upload/cancel 추가 — 실패한 업로드가 열린 업로드 3개 한도를 하루 동안 막던 문제.
  • 보기 토큰 6시간 (가이드 예시 24시간보다 짧게) — 숨김·비공개 전환이 빨리 반영되게. 긴 영상은 플레이어가 새 주소로 이어 재생.
  • web.json video.transcode 와 library/y2b_transcode.py·shell/y2b_transcode_worker.py 는 로컬 파일 전제라 더 쓰지 않는다. finish 는 항상 status='ready'.
